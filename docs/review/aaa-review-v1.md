## 1. 总判定

**总判定：FAIL**

一句话理由：**这是一份合格的"工程垂直切片"，但离"可展示样品"还差整整一个美术与表现层——它的 UI 有 3/7 屏根本没套设计系统、选职业屏几乎没按规格实现、HUD 只做到线框级、角色是基本体堆叠且所有职业共一把盒子武器、场景是一块平底、音效为零。按 §2 的每一条门槛逐项判定，无一项达到"达标"，其中 2.2 / 2.4 直接未达标。**

离可发布还差的量级：**当前处于"白盒技术演示 → ghost 级灰盒样品"之间**。要到达"可对外展示（投资者/发行商 demo）"，缺口集中在**表现层（presentation）**而非战斗逻辑：UI 设计系统覆盖、角色造型与材质分层、武器家族外形、场景光照与构图、音频四层——这五项都是**从 0 到 1**，不是"打磨"级别的工作。按 §2 逐条对表，**27 个验收勾选项里，判定达标 0 项、部分达标 6 项、未达标 9 项、无法验证 1 项**（另 11 项属占位残留 / 可访问性细项，并入对应条）。

> 注：战斗逻辑（确定性与事件流）看起来是扎实的，但那不是本次 §2 的评分对象——§2 评的是**玩家看得到、摸得到的东西**，而这正是缺口所在。

## 3. 缺陷清单（按严重度排序）

### D1【致命】摄像机与构图不可读，对局像"俯视一个煎饼"
- **现象**：对战中中央擂台占满画面，角色极小，对手常常读不到；背景是空白 void。
- **证据**：shot-02（擂台暖白面占下半屏 2/3；角色约 85×80px；仅 1 名角色清晰可见；背景为平色 + 两个悬空黑盒）。代码：`CameraFactory.cs:25–27`（`back∈[9,17]`，俯角约 35°，正对 `AddCylinder` 的 r=8 圆台，`ArenaBuilder.cs:126–127`）。
- **为什么是问题**：违反 §2.3"构图可读"与支柱 3"值得看/像转播"。竞技游戏旁观者读不出战况 = 失去观赏性这一存在理由。
- **修复方向**：改为**对战机位而非全景机位**——降低俯角、拉近（越肩或 1/4 侧视），按双方间距**自适应推拉**；开局/大招/终结给专门运镜；保证任何时刻双方都在安全框内。

### D2【致命】角色是基本体堆叠，且全职业共一把盒子武器
- **现象**：蓝色圆块 + 盒子，无法分辨职业武器；24 职业共用一个 `BoxMesh`。
- **证据**：`FighterMeshBuilder.cs`（14 件 Box/Capsule/Sphere/Prism/Cyl）；`FighterView.cs:62`（`Mesh = new BoxMesh{Size=(0.08,0.90,0.08)}` 恒定）。shot-02 中角色为蓝色基本体团。
- **为什么是问题**：art-bible §2.2 自定"不是胶囊+盒子"、§4.4 定义了 20 种武器剪影——**两条自定标准都被自身实现违背**。无模型、无 `.glb`（`assets/` 不存在）。
- **修复方向**：① 先按 art-bible §4.4 做**武器家族外形**（至少本阶段 3 职业 BMG/BLA/SRP），从 `weapons.csv` 的 `type` 驱动；② 角色在"骨架 + 系别变体件"基础上补**每系一件差异件**（§3.3）；③ 接入真模型是终局路径。

### D3【致命】阵营在纯黑剪影下不可分（违反竞技第 0 号红线）
- **现象**：team0 与 team1 是两具完全相同的人形；阵营只靠颜色。
- **证据**：`FighterMeshBuilder.cs:62–97` 的变体件按"系"分、**无一件按阵营分**；art-bible §2.2 要求的④地面环形状、⑤肩徽形状**未实现**；出生标记仍是红/蓝（`MatchRoot.cs:281–282`，art-bible §2.2 建议改橙，仍未改）。
- **为什么是问题**：色盲玩家 / 灰度直播 / 缩略图里敌我不分。§3.2 剪影测试的"阵营 100%"当场失败。
- **修复方向**：给每阵营一套**几何冗余**——肩徽形状（方/圆）+ 地面环（尖角 vs 圆齿）+ 角色边缘描边；出生标记改橙。

### D4【高】选职业屏几乎未按 ui-spec §3.2 实现，且不套设计系统
- **现象**：整屏只有三行 `Label`，居中文本列表，无面板/详情栏/八维条/技能预览。
- **证据**：`ClassSelectScreen.cs:34–51`（仅 `_title/_body/_hint`），Redraw 为字符串拼接（第 107–116 行）；字号硬编码 30/20/16。shot-03 证实为居中文本 + ▶。
- **为什么是问题**：这是玩家见到的**第一个游戏界面**，ui-spec §3.2 定义的双栏面板是"旗舰屏"。当前形态像调试输出。
- **修复方向**：按 ui-spec §3.2 补双栏面板（列表 + 详情：职业名/系别·护甲/定位三联/八维条/技能预览），全部走 `UiTheme`。

### D5【高】HUD 大量规格未实现
- **现象**：技能栏无图标、无冷却秒数、无禁用态；对手血条无 45° 条纹；无连段/状态图标；技能名 13px 且被屏幕底边裁切。
- **证据**：`Hud.cs:157–166`（CD 只有黑矩形，无秒数）、`:136`（font 13 < 14）、`:133`（名称 y=702 触底）、`:115`（纯色块非图标）、`:32–38/51–58`（无条纹通道、无 MP 不足态）。
- **为什么是问题**：技能栏是最高频读取区，ui-spec §3.4 的绝大多数元素缺席。
- **修复方向**：按 ui-spec §3.4 补齐——档位色外框技能图标（文字可用）+ 冷却秒数居中 + MP 不足红框 + 对手血条斜条纹 + 名字板带血条。

### D6【高】全平台零音频
- **现象**：无任何音效/音乐。
- **证据**：`Grep`/`Glob` 无音频产物；`OPEN-ISSUES.md` EN-04。§2.4 三条全 fail。
- **为什么是问题**：支柱 2"打得爽"= 顿帧/火花/数字/声音四层，声音是分量最重的一层。
- **修复方向**：建立最小 `AudioDirector` + 4 层音源（命中/受击/技能/UI），先程序化合成亦可；普攻与大招做显著轻重差。

### D7【中】设计系统未贯穿 + 无内置 CJK 字体
- **现象**：3/7 屏绕过 `UiTheme`；`WeaponSelectScreen` 用绝对 `Position`（不随分辨率缩放）；无捆绑字体。
- **证据**：`WeaponSelectScreen.cs:15,47–48,61–64`（Position 而非锚点）；`ClassSelectScreen.cs:37,42,47`；`Hud.cs` 全文；`src/Arena.Client/assets/**` 不存在 → 无 OFL 字体资源。PRODUCTION-PLAN §5 明令"界面需内置 CJK 字体"。
- **为什么是问题**：换分辨率/换语言即崩；系统无 CJK 字体时会显示"豆腐块"。
- **修复方向**：所有屏改用锚点 + `UiTheme` token；内置一份 OFL 中文字体（`res://assets/ui/`）并在 `project.godot` 设为默认主题字体。

### D8【中】曝光/氛围偏离自定规格
- **现象**：画面读作暖白平板，非 art-bible §1.2 的"冷峻、硬朗、高对比"。
- **证据**：`ArenaBuilder.cs:71,79,89`（三灯能量 0.70/0.15/0.25，均低于 art-bible §5.1 的 1.0–1.2/0.25–0.35/0.5–0.7）；shot-02 中主平底接近 #FFFFFF 暖白，未见轮廓光。
- **为什么是问题**：自定照明规格在实现时被系统性压低，导致 A2/A3 依赖的分离度消失。
- **修复方向**：恢复至规格能量区间；若担心无色调映射过曝，应加 tone mapping 而非砍灯。

### D9【中】术语/颜色链条不一致（红→橙 迁移不彻底）
- **现象**：视觉已是蓝/橙，但文案仍是 "RED WIN"；出生标记仍为红。
- **证据**：`MatchRoot.cs:430`（`"RED WIN"`）、`:282`（`new Color(1f,0.3f,0.3f)`）；art-bible §2.2 待裁定 A 未落。
- **为什么是问题**：文档、视觉、代码各说各话，是评审与联调的噪音源。

### D10【低】HUD 元素在屏幕上互相堆叠
- **现象**：伤害数字、双方名牌堆在同一处，糊成一团。
- **证据**：shot-02 约 x≈640、y≈230–285（"198" / "P1 100" / "BOT 93" 三行叠加在角色头顶）。
- **修复方向**：伤害数字与名牌做垂直错位/抖动偏移，避免同点叠加。

### D11【低】截图证据陈旧、互相矛盾

## 4. 与三个标杆的差距

### vs 守望先锋（Overwatch）
- **它做对了**：① 敌人**恒定红色描边**（与颜色无关的形状/轮廓通道，实现"剪影+描边"双编码）；② 团队色**大色块**铺满躯干四肢；③ **转播级构图**——击杀镜头、大招视角、镜头跟随永远把交战双方框好；④ 打击反馈音画同步（命中音 + 火花 + 数字）。
- **我们缺**：描边通道（D3）、转播构图（D1）、命中音（D6）、角色成型的剪影（D2）。**一句话**：OW 让旁观者 0.3 秒内知道"谁在打谁、谁占优"；我们在 shot-02 里连第二个人在哪都读不出。

### vs 英雄联盟（LoL）
- **它做对了**：① 顶部**对称镜像**的双方资源条（头像 + 血/蓝 + 数值）；② 底部技能栏 = **图标 + 冷却秒数 + 等级点**，信息密度高但一眼可读；③ 明确的"己方蓝 / 敌方红"信息层；④ HUD 全部元素绑定同一套 design token。
- **我们缺**：镜像对称做到了（`Hud.cs:55` 修正了 x=846），**但技能栏缺图标/秒数（D5）**、且 3 屏绕过 token（D7）。**一句话**：LoL 的技能栏回答"我现在能放什么、CD 还有几秒"；我们的技能栏是一个黑洞，答不出来。

### vs 魔兽世界（WoW）
- **它做对了**：① **世界空间**的姓名板 = 名字 + 血条 + 状态图标一起挂在目标头上；② 材质/光照分层让体型与装备可辨；③ 状态（眩晕/定身）用**图标**而非仅颜色。
- **我们缺**：名牌只有文字（`FighterView.cs:78–84`，`Label3D` 仅名字+HP 数字，**无血条、无状态图标**），状态仍只靠颜色（`FighterView.cs:99–108`），材质未分层（D2/2.2）。**一句话**：WoW 的世界空间信息层让玩家不切 HUD 就知道目标状态；我们的头顶只有三行会叠在一起的文字（D10）。
