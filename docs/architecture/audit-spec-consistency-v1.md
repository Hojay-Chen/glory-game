## 1. Executive Summary

**总体判断：三者总体兼容，无不可逾越的阻塞项，可在完成 4 项裁定后进入 ADR-0001。**

- **时间表达**：Skill-Spec 设计层采用「60fps 整数帧为主 + 秒为辅」的混合口径。由于仿真恰好是 60 Tick/s，**帧字段与 Tick 1:1 映射，零量化误差**；全部秒值 ×60 后均为整数 Tick（唯一的非整 Tick 秒值 0.68s/0.82s 只出现在天击的 notes 注释里，不是运行时字段）。Design→Runtime 的量化管线可行，但需要 ADR-0001/0002 明确三项政策（见 §4）。
- **技能表达能力**：487 条技能（**注意：任务书写的 532 是旧版 README 的过期数字，当前 skills.csv 实际 487 行**）全部可被当前架构表达：A 纯数据 162 / B 标准 Rule Modifier 265 / C 签名插件 60 / **D 无法表达 0**。但 B 类中有 12 项能力是当前 Core 模块清单**尚未列出接口**的（吸收盾/反弹/CD 操作/单位系统等），属于「架构缺口需补接口」而非「无法表达」——详见 §5。
- **最大风险不是表达能力，是确定性纪律**：①**14 条技能含几率/随机字段**，与 GDD D02「无随机」直接冲突（BLOCKER 级裁定项）；②伤害修正系数的浮点幂运算（×0.8ⁿ 等）跨平台不可复现，必须定点化（正是 ADR-0001 的议题）；③3 处文档口径漂移（Skill-Spec README 散人池 94≠96、armor 字段 s/f 单位混用、active_f 形态词未入字段字典）。
- **事件边界**：架构已通过 `ISimContext` 受限 API 解决「Feature 不得直改 Core 状态」（§八 通过，附 2 条需在 ADR-0003/0008 固化的细则）。

**结论：READY（有条件）——完成 §2 列出的 1 项 BLOCKER 裁定（几率字段处理口径）与 3 项 HIGH 项的归档后，即可进入 ADR-0001；其余条目不阻塞 ADR 编写，只阻塞对应系统的实现。**

## 3. Skill Expressiveness Report（487 条全量分类）

分类判据（基于 architecture.md 实际模块，非感觉）：
- **A**：special 无机制语义（'-' 或纯描述/调优注记），全部行为由标准字段（hitbox/damage/status/launch/knockback…）+ SkillRuntime/HitResolve/Gates/Status/Projectile/Terrain 标准路径表达
- **B**：需要标准 Rule Modifier 接口——蓄力/延迟/部署/结界/追踪/拦截/穿透/背身/要害/对空/抓取参数/吟唱/引导/位移系/倒地系/霸体系/减伤盾/光环/治疗/驱散/CD 操作/精度段数/可控弹道/部位结算/几率修饰（若 B-1 裁定为种子化随机）——不需要职业专属状态
- **C**：依赖职业签名机制（Classes.Signatures / ISignature / ISimContext）——职业专属资源（炫纹/血气/弹匣/召唤位/部署位）、单位 AI、隐身/分身/替身、形态切换、结印输入序列、跨技能变异、事件回溯复制
- **D**：当前架构任何模块组合均无法表达

| 分类 | 数量 | 占比 | 示例 | 原因 |
|---|---:|---:|---|---|
| **A** | **162** | 33.3% | 全部普攻段（79）、上挑、火焰爆弹、破魔斩、月光斩、体术系、波动剑×6、鹰踏段、描述性注记技（「判定强劲」等） | 纯标准字段；special 为风味/调优文本 |

|---|---|---|---|

| invincible_f / armor | 帧区间（`4-14f` / `SA:30-40f`） | armor 1 行用 s（H-2） | ✅（H-2 修正后） |
| 弹道/运动（proj 速度 m/s、launch_v 6.5–9.0、重力 22） | 连续物理量 | — | ⚠️ 不存在「Tick 对齐」问题，但**定点积分策略**是 ADR-0001 的核心议题（OQ-1）：建议速度换算为 per-Tick 定点位移（如 1/1000 m/Tick），重力同理；禁止 `v += g*dt` 浮点累积 |

**结论：不存在任何无法映射到 60 Tick 的运行时时间数据。** 唯二非整 Tick 秒值（0.68s/0.82s）只出现在天击 notes 注释中，非字段值。

### 4.2 Design → Runtime 转换管线（当前架构支持度）

```
Skill Design Data (CSV: 帧整数为主 + 秒辅 + 形态词)
        ↓ Data.Catalog 导入（解析 8 种已核实的书写格式）
Data.Validate（新增建议见 §7-R4：Tick 网格校验/格式白名单/几率数值存在性）
        ↓ 量化：帧字段恒等映射；秒字段 ×60（已验证全整数）；形态词 → Runtime 模式标志
Runtime SkillDef（强类型 record，Tick 单位 int + 模式枚举）
        ↓
60 Tick Simulation（SkillRuntime 支持 standard / maintained / controlled / delayed 四种 active 模式）
```

**当前架构能够支持该转换**——Data.Catalog 的双导出设计（TR-live-002）正是这个管线；缺口仅在「格式白名单与量化政策未成文」（M-1~M-4），全部属于 ADR-0002 内容。

### 4.3 量化误差是否会改变战斗行为

- 帧字段：无误差（整数恒等）。
- 秒字段：无误差（全部整 Tick）。
- **有误差风险的三处**（均需政策而非数据修改）：①武器攻速乘帧（M-4）——±1 Tick 会改变连段窗口；②多段命中均匀分布的 round 方向（M-2）；③物理积分定点化精度（H-1/OQ-1）。三项都有确定解，进入 ADR 即可。

## 8. ADR-0001 Readiness

**READY**（有条件）

理由：
1. **时间层面无阻塞**——全部运行时时间字段可零误差映射到 60 Tick（§4.1），Design↔Runtime 转换管线可行且缺口（量化政策 4 项）正是 ADR-0001/0002 的预定议题，不构成前置障碍
2. **表达能力无阻塞**——D=0；A/B/C 分布证明「标准规则接口为主（90%）、签名插件为辅（12%）」的架构判断成立
3. **确定性风险已识别且有解**——H-1（浮点幂）/C-9（白盒 float 不可移植）/C-10（容器序）全部收敛为 ADR-0001 的定点化议题，且白盒已实证算法层可行

条件（不改变 READY 判定，但 ADR-0001 内容必须涵盖）：
- ADR-0001 必须包含：定点数值单位制（OQ-1）、预计算系数表替代 pow（H-1）、Sim 内有序容器纪律（C-10）、武器攻速/多段时刻表/active='-' 三个量化政策（M-2/M-3/M-4）
- B-1（几率 vs 无随机）是**设计裁定**不是 ADR-0001 的技术议题——但 ADR-0003（事件协议）若裁定种子化随机合法，需同步收录；建议 B-1 与 ADR-0001 并行裁定，不互相阻塞
- §5 表 9 项接口缺口在 ADR-0008（签名协议）与实现 stories 中落地，其中 UnitSystem/VisibilitySystem 建议升格为独立 ADR（Alpha 前必须）
