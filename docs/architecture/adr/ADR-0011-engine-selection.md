# ADR-0011：引擎选型 —— 维持 Godot 4（不迁 Unreal Engine 5）

- **状态**：Accepted
- **日期**：2026-10-14
- **触发**：用户多次提出"黑神话悟空用的是 UE5，是不是换 UE5 更容易做到 3A 画质"

---

## 1. 背景

用户的目标是**画面/场景/角色美术对标 3A（黑神话悟空量级）**，并质疑 Godot 能否承载。
本 ADR 记录**为什么维持 Godot**、UE5 的真实优势在哪、以及在什么条件下应当重新评估。

## 2. 决策

**维持 Godot 4.3 + Forward+ 渲染管线。不迁移 Unreal Engine 5。**

## 3. 依据

### 3.1 UE5 的客观优势（承认，不回避）

| 能力 | UE5 | Godot 4.3 |
|---|---|---|
| 几何 | **Nanite**（电影级网格免 LOD） | 无等价物，需传统 LOD |
| 全局光 | **Lumen**（动态 GI 免烘焙） | 有 SDFGI/LightmapGI，质量与易用性不及 Lumen |
| 角色 | **MetaHuman**（写实角色生成） | 无等价物 |
| 特效 | **Niagara** | GPUParticles3D，表现力较弱 |
| 动画工具 | **Control Rig / AnimBP** | AnimationTree，功能够用但弱一档 |
| 资产生态 | 最大（Fab / 大量教程与外包） | 较小 |
| 主机移植 | 官方支持 | 需第三方（W4 Games） |

**结论：对"有美术团队的 3A 项目"，UE5 通向高画质的路径确实更短。**

### 3.2 但本项目的实际约束使迁移**不可行**（实测数据）

| 项 | 云服务器（全部开发在此） | Windows 主机 |
|---|---|---|
| GPU | **Cirrus Logic GD 5446**（虚拟显示适配器，无 3D） | RTX 5070 |
| 磁盘可用 | **2.4 GB**（UE5 需 ~120 GB） | 182 GB |
| 账号权限 | root | **`jay\devops` 非管理员**（装 UE5 需 UAC） |

- **云上无法构建/运行 UE5**——本项目的**全部**工程动作（编译、262 项测试、无头渲染验证画面、
  素材处理）都发生在这台机器上。换引擎 = 开发活动归零。
- Windows 侧**物理可跑**（有独显、有空间），但**安装需管理员**，且装成后我只能隔着 SSH
  驱动一个 GUI 优先、C++ 编译缓慢的工具链，迭代速度大幅下降。

### 3.3 迁移会摧毁项目最核心的资产

现有价值的大头是**引擎无关的工程资产**，且**不能移植**：

- 确定性帧同步战斗 Sim（Q32.16 定点、回滚、`Arena.Core`，**262 项测试**）
- 帧数据驱动体系（`skills.csv` 488 行：startup/active/recovery、取消档位、跳跃取消）
- 取消窗 / 浮空连招 / 输入缓冲等《荣耀》机制（已实测生效）
- ADR-0001~0010 的架构契约与 Gate

UE 的网络模型是**状态复制**，与**帧同步 lockstep** 是两套范式——迁移不是"移植"而是"重写数月"。

### 3.4 关键认知：引擎不是 3A 画面的来源

黑悟空的画质来自：**手工雕刻资产 + 逐帧手 K 的战斗动画 + 动捕采集 + 美术/特效团队**，
UE5 只是让这个团队更省力。**没有美术与资产管线时，换引擎只会得到"全局光更漂亮的白盒"。**

本项目当前的真实瓶颈是 **资产与管线**，不是渲染器能力：
一张 60×84m 竞技场 + 2 角色 + 1600 实例观众，对 Forward+ 是**轻负载**；
Godot 已有《Road to Vostok》（单人 3D 硬核射击，发售 1 天回本）、《杀戮尖塔 2》
（首周 300 万套）等大体量商业作品。

## 4. 重新评估的触发条件（三条同时成立才考虑）

1. 有**我可自由操作、具备管理员权限 + 独显**的 Windows 机器，可无人值守构建 UE5；
2. 用户接受**战斗系统按 UE 范式重写**（周期以月计），而非移植；
3. 用户接受**迭代速度显著下降**（GUI 工具链 + C++ 编译）。

> 注：若将来需要**主机发行**或**写实人物**（MetaHuman 级），条件 1 通常也会一并满足，
> 届时本 ADR 应被 superseded。

## 5. 后果

- **正面**：全部既有工程资产保留；开发可持续；画面改进按里程碑推进（见 §6）。
- **负面**：放弃 Nanite/Lumen/MetaHuman；写实上限低于 UE5；主机移植需另寻方案。
- **缓解**：通过 **Forward+ 能力用满 + CC0 高质量资产（Poly Haven 等）+ 后期栈**
  把画面推到"像样的商业独立游戏"水准；角色/动画短板靠动捕重定向与生成工具补齐。

## 6. 替代路线（M5 起的美术里程碑，取代换引擎）

M1 渲染管线（Forward+/ACES/体积雾/SSAO/泛光）✅ · M2 实拍 PBR + 星空 HDRI ✅ ·
M3 灯光体系 ✅ · M4 人群 + 建筑层 ✅ · **M5 真模型资产替换基本体** · M6 角色多套模型 ·
M7 战斗 VFX 库 · M8 后期栈（景深/LUT/颗粒） · M9 动画分层（AnimationTree + 更多动捕）
